## 최종 방향

사용자가 승인한 실사 날씨의 감성을 기준으로 S1~S8과 인증·설정 하위 화면을 대조했습니다. 날씨는 실제 하늘·달·빗방울 사진, 나머지는 중성 배경·명확한 글자 위계·충분한 여백을 유지합니다. 규격은 [디자인 시스템](../../../DESIGN_SYSTEM.md)이 기준입니다.

- 하단 바의 elevation을 0dp로 낮춰 입체적인 회색 그림자를 제거했습니다. 실제 배경 블러·반투명 중성 표면·선명한 아이콘은 유지합니다.
- 홈·용품·캘린더의 항목 컴포넌트와 설정·상세·가족·폼의 행동 행을 점검했습니다. 생성한 행동 행에도 테마 ripple을 적용해 기존 XML 목록과 터치 반응을 맞췄습니다.
- 세탁과 욕실 청소 아이콘을 구분하고 설정의 권한 행에도 같은 1.75dp 선 두께의 벡터 아이콘을 배치했습니다.
- 용품 목록의 중복 설명을 필터별 개수로 바꿨습니다. 날씨 예보에 최저·최고 열 설명을 넣고 ‘세탁하기 좋아요’의 띄어쓰기를 고쳤습니다.
- 회원가입·로그인·등록·상세·가족 관리는 공통 Pretendard·색상·버튼·필드·제목 규격으로 유지합니다. 모든 페이지를 사진이나 유리 카드로 덮지 않습니다.

## 검증

macOS arm64 · JDK 17 · Android Emulator API 36 / arm64-v8a · 1080×2400·420dpi·fontScale 1.0. 작은 화면은 같은 해상도·461dpi(약 375dp)입니다.

명령: `JAVA_HOME=$(/usr/libexec/java_home -v 17) ./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`

- 빌드 성공. JUnit 10개, 실패·오류·건너뜀 0. Lint 오류 0·고정한 의존성/도구의 새 버전 안내 경고 15.
- `./scripts/design/preview.sh --serial emulator-5554 --no-build` 실제 설치·실행.
- 주요 경로 15개를 라이트·다크에서 열고 캡처했습니다. 예시 로그인 오류→홈, 완료→다음 예정일·이력, 등록→상세→원래 목록은 최초 실행에서 확인했습니다.
- 최초 실행은 회전 후 초안 이탈 확인창에서 취소 버튼을 찾지 못해 중단됐고, 직후 ADB 목록에서 가상 기기가 사라졌습니다. 종료 원인은 확정하지 않습니다. 기존 AVD를 데이터 삭제 없이 재실행하고 같은 APK를 설치했습니다. 회전 초안 유지·이탈 취소는 재실행해 통과했습니다. 최초 실패 로그는 보존하며 전체 스크립트 1회 완주라고 쓰지 않습니다.
- 재실행에서 빈 목록·오류·로딩·오프라인, 아침·낮·저녁·밤·비, 홈 패널·스크롤 끝, 375dp 홈·캘린더·가입·등록을 확인했습니다. 기본 예시를 초기화하고 홈으로 복원했습니다.
- 추가 실행에서 전체 3개→욕실 2개→주방 1개 필터 개수, 권한 행의 알림 화면 진입, 라이트·다크 등록/가입 폼의 제출 버튼까지 스크롤을 확인했습니다. 375dp 날씨의 예보 열 제목은 처음 화면에, 세탁 조언은 스크롤 뒤에 노출됩니다. 최초 추가 실행은 스크롤 전 조언을 찾다가 실패했고, 별도 재검증에서 실제 스크롤 뒤 문구·캡처를 확인했습니다. 두 로그를 구분해 보존합니다.
- APK SHA-256: `cb4bdaef8a3baabb6beaa6c15d56e72333dfaed5b1658ade6c14ab5b7da0055b`.
- 로컬 전체 로그는 `app/build/reports/design/cohesive-build.log`, `cohesive-ui.log`, `cohesive-recovery.log`, `cohesive-details.log`, `cohesive-small-recheck.log`에 보존합니다. APK와 전체 로그는 Git에 넣지 않습니다.

실제 인증·서버 저장·예보·초대·알림·OCR은 연결하지 않은 디자인 미리보기입니다. 시스템 다크·기기 시각 사진·로컬 예시 동작을 제품 연동 성공으로 간주하지 않습니다. 실기기·태블릿·API 26~30·TalkBack·성능 계측은 미검증입니다. 큰 글씨 별도 버전은 제작하지 않았습니다.

## 시각 검토

`sip` → `shower`의 별도 문맥 검토에서 8화면의 화이트·중성 표면·주요 버튼·상태 색과 글자 위계가 일관되며 시각적 차단 문제는 없다는 결과를 받았습니다. 등록 버튼이 초기 스크롤 화면 아래에 있어 등록·가입은 하단 캡처도 제공합니다. 달력 점의 의미가 처음에는 미묘하다는 의견은 선택 날짜 목록·접근성 설명을 유지하는 범위로 남겼고 새 설명 장식은 추가하지 않았습니다. 다크 보드는 별도로 직접 확인했습니다.

## 기여와 인계

사용자(성명 확인 필요)는 사진 감성 및 전체 화면 방향을 승인·지정했습니다. Codex 도구는 공통 컴포넌트·아이콘·문구 구현과 화면 대조·자동·시각 검증·기록을 수행했습니다. 팀원의 승인이나 실사용자 사용성 평가를 대신하지 않습니다.

기존 `feature/design-system-foundations` 작업을 이어갔습니다. `git fetch origin main`은 `Repository not found`로 실패해 이슈·PR·push를 수행하지 못했습니다. 마지막 확인 가능한 원격 기준은 `8511eb9408f3203cc2f8821630d854e7716171bd`이며 최신성은 확인하지 못했습니다. main 병합·브랜치 정리는 수행하지 않았습니다.
