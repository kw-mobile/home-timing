## 빌드와 동작

명령: `JAVA_HOME=$(/usr/libexec/java_home -v 17) ./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`

- APK 빌드 성공. 실제 JUnit **10개**, 실패 0·오류 0·건너뜀 0: 시간대 2, 예시 저장소 4, 화면 상태/이동 2, 임계 감쇠 스프링 2.
- Lint **오류 0·경고 15**. 경고는 고정한 의존성·도구의 새 버전 안내이며 이번 작업에서 버전을 바꾸지 않았습니다.
- `bash -n scripts/design/preview.sh`, 실제 스크립트의 APK 설치·실행, `git diff --check` 확인.
- 로컬 로그: `app/build/reports/design/build.log`, `main-ui.log`, `additional-ui.log`, `landscape-recheck.log`, `home-header.log`. 생성 파일이므로 Git에는 포함하지 않았습니다.
기본 UI 자동화는 위 최종 APK에서 최종 전체 실행이 성공했습니다. 추가 확장 시나리오는 `558c4707e3dcedb507c2301470756e4476799beb`에서 검증했고, 이후 홈 고정 제목과 메뉴 이름 변경은 최종 APK에서 별도로 재검증했습니다. `adb`·실제 UIAutomator 계층·터치 입력·화면 캡처를 사용했습니다. 별도 계측 테스트나 실제 서버 검증으로 바꾸어 쓰지 않습니다.

추가 UI 실행의 마지막 가로 캡처는 시스템 회전 전환 중인 프레임을 잡아 한 번 실패했습니다. 같은 APK에서 회전 완료를 기다린 뒤 해당 시나리오를 별도 재실행해 통과했습니다. 실패 흔적은 `additional-ui.log`에 보존하고 재검증은 `landscape-recheck.log`에 구분했습니다. 앱 크래시로 기록하지 않았으며, 검증 도구의 대기와 실제 화면 배치를 구분했습니다.

검증 후 예시 항목·설정을 초기화하고 홈, 기기 시각 자동 적용, 라이트 모드, 420dpi, 글자 배율 1.0, 원래 회전·모션 설정으로 되돌렸습니다. 설치 직후 에뮬레이터 콜드 시작은 약 15~17초로 관찰했으며 실기기나 프레임 성능의 측정값은 아닙니다.

## 시각 검토와 한계

`sip` → `shower`의 별도 문맥 검토에서 8화면 보드와 홈·등록·다크 홈을 읽었습니다. 홈 하단 제목의 노출, 시작일 의미, 완료 후 계산 기준을 지적받아 하단 안전 영역·시작일 설명·다음 예정일 미리보기·완료 확인창을 보완했습니다. 추가 검토를 반영해 홈 제목·등록 버튼을 고정하고, 미리보기 진입 이름을 ‘화면 모음’으로 바꿨습니다. 등록은 스크롤 폼이며 제출 버튼까지 내려간 캡처도 제공합니다. 팀원의 승인이나 실제 사용자 사용성 평가를 대신하지 않습니다.

색상 토큰의 일반 텍스트 대비는 라이트·다크 모두 4.5:1 이상입니다. 본문 17.01/17.46, 보조 글자 5.70/8.43, 주요 버튼 글자 12.50/9.70입니다. 사진의 균일한 검정 scrim은 가장 밝은 원본 픽셀 위에서도 흰 글자 대비 약 4.74:1을 확보하도록 설정했습니다. 이 계산은 실제 TalkBack·전체 화면 접근성 감사를 대신하지 않습니다.

사진은 실사 스톡을 APK에 포함한 예시이며 실시간 카메라·위치 사진이 아닙니다. 아침/낮 및 흐림/비는 각각 같은 사진을 재사용합니다. 실제 인증·서버 저장·기상청·알림·초대·OCR은 연결하지 않았습니다. 스와이프·완료·등록·가족 참여는 로컬 예시 동작입니다. API 26~30 유리 대체 표면, 실기기, 태블릿, TalkBack, 성능 계측은 미검증입니다. 별도 큰 글씨 버전은 만들지 않았습니다.

README·MVP·디자인·아키텍처의 범위와 링크를 대조했습니다. 이전 HTML과 3탭 증거는 역사 기록이며 현재 시안은 이 폴더입니다. 화면 캡처/문구 확인을 실제 API 성공이나 제품 기능 완료로 간주하지 않습니다.
