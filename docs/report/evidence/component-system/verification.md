# 컴포넌트·전체 화면 공유 검증

2026-11-10 · 최종 앱 코드 `42d2040` (전폭 날씨·화이트 본문·패널 상단 경계/그림자 포함) · JDK17 · macOS arm64 · API36 arm64 에뮬레이터 `Medium_Phone_API_36.1`.

사용자는 디자인 담당으로 최신 스타일·기존 폰트 크기를 유지하고, 팀원이 응용할 컴포넌트와 기존 전체 화면의 공유용 HTML을 요청했습니다. Codex 도구가 Java/XML·로컬 사용 예시·규격·HTML·검증을 작성했습니다. 실제 서비스 구현/팀 승인으로 기록하지 않습니다.

## 범위

- 기존 S1~S8·4탭과 인증/설정 하위 화면을 포함합니다.
- 제안·선택 정보·주기 예시·완료일 View가 화면과 개발용 모음에서 사용됩니다. 모두 외부 값/콜백을 받아 표시하며 PreviewStore/Firebase/HTTP를 의존하지 않습니다.
- [디자인 시스템](../../../DESIGN_SYSTEM.md#팀원-적용용-컴포넌트-계약)에 입력·상태·이벤트·길이·배치·권한/저장 경계를 둡니다.
- [독립형 HTML](../../../design-review.html)은 실제 캡처 모음입니다. 이미지가 포함된 파일 하나로 공유하며 실제 앱 기능을 수행하는 웹앱은 아닙니다.

미리보기 이미지 표시에서 날씨 글자가 빠져 보인 현상을 앱 결함으로 의심했으나, 별도 문맥 이미지 검토와 실제 PNG에 대한 OCR은 기온·최고/최저·조회 시각을 확인했습니다. 당시 색/alpha/높이 진단도 정상이라 재현된 앱 결함으로 판정하지 않습니다. 임시 진단 로그는 제거했습니다. 배경 표본은 부착 View/Layout/Drawable을 직접 그리지 않고 독립 복사본을 사용하도록 분리했습니다. 실제 앱 렌더링 오류가 해결되었다는 근거로 삼지 않습니다.

화이트 본문·큰 전폭 날씨 사진(홈320dp/상세360dp), 패널 상단0.5dp 중성 경계·12dp 네이티브 그림자·핸들을 최신 방향으로 적용했습니다. 확대 폰트 검사는 하지 않았습니다. 정상 경로·하위 화면·상태/날씨는 최종 코드 `42d2040`에서 일괄 캡처했습니다. 별도 입력 검증 이미지는 당시 SHA를 파일별로 보존합니다.

[라이트 8화면](overview-light.png) · [다크 8화면](overview-dark.png). HTML은 **79장**, 이미지 포함 약22MB입니다. Chrome157에서 네트워크를 끊고 로컬 파일을 열어 라이트/다크·컴포넌트 필터·확대/닫기와 1440px/390px에서 가로 넘침 없음을 확인했습니다. 휴대폰 실브라우저 공유 앱의 HTML 첨부 정책까지 검증하지는 않았습니다.

캡처마다 앱 SHA·테마·화면/상태·파일은 [manifest.json](manifest.json)에 있습니다. 스크롤 아래 영역은 같은 화면의 추가 캡처로 구분합니다. 기본·라이트/다크·컴포넌트·상태/날씨를 필터로 확인합니다.

검사 초기에는 완전한 문구가 아닌 부분 문구로 검색한 harness 실패, 공백 문자열 입력/화면 밖 필드 검색/영문 날짜 선택기의 한국어 버튼 검색 실패, 테마 전환 후 재시작 타이밍, 에뮬레이터 프로세스 종료가 있었습니다. 원래 회차 날짜/유지 문구가 실제로 화면에 있었던 실패와 기기 연결 실패를 제품 성공 결과에 합치지 않습니다. 재실행 결과를 별도로 남깁니다.

별도 문맥의 컴포넌트 계약 검토에서 같은 값 재바인딩 시 `setText`가 커서를 초기화하는 문제를 찾아 수정했습니다. 실제 값이 같으면 건드리지 않고 외부 값이 바뀌면 선택 위치를 가능한 범위에 보존합니다. 필수 콜백/외부 길이 검증/제안 상태 문구/주기 가로 스크롤 소유권도 명시했습니다.

로그는 ignored `app/build/reports/design/component-*.log`에 보존하며 APK·개인 SDK경로·키는 커밋하지 않습니다. 바코드 도구12개·Notion 도구16개 모의 테스트도 기존 포함 변경의 회귀로 확인했고 실제 API/Notion 성공을 뜻하지 않습니다.
