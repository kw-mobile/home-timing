# 승인한 홈 디자인·전체 화면 공유 검증

2026-11-10 · 최종 앱 `7eeb4a82ae162900b8ed1f2391838029e773f8db` · 캡처 `7daec1c5893bee87c097211b531e812fd9c2f609`.

사용자(성명 확인 필요)는 디자인 담당으로 라이트·다크 시안을 확인한 뒤 현재 방식의 업로드와 전체 HTML 재생성을 승인했습니다. Codex 도구가 XML/Java·컴포넌트 규격·캡처·HTML·검증을 작성했습니다. 사람의 코드 리뷰나 실제 서비스 구현 완료로 대신 기록하지 않습니다.

## 최종 디자인

- 흰 본문·중성 유리 하단 바·실사 사진·기존 폰트 크기를 유지합니다.
- 홈 상단 바 바로 아래부터 전폭 사진이 시작됩니다. 날짜·위치·기온을 한 사진 영역에 넣고 고정 ‘오늘’ 제목은 제거했습니다. 홈420dp·날씨 상세360dp입니다.
- 날짜는 화면 표시·앱 복귀·기기 시각 이벤트에 따라 서울 기준 현재 날짜로 갱신합니다. 다음 날짜의 예보를 선택해 홈을 바꾸는 기능은 연결하지 않았습니다.
- 모달의 **위쪽 둥근 모서리 바깥**에 그림자가 퍼집니다. `SheetShadowView`는 패널의24dp 위에서14dp 블러 그림자를 그리며 이동·펼침·숨김을 따릅니다. 핸들은 투명한48dp 터치 영역이며 별도 회색 띠나 핸들 아래 그림자는 없습니다. 기본 반 높이는 유지합니다.
- 나머지 S1~S8·가입/설정 하위 화면·컴포넌트와 빈 상태/오류/오프라인·시간대별 사진도 같은 갤러리에 포함합니다.

날짜·완료 이력·주간 회차·실제 완료일·미래/과거 거부·중복·되돌리기·수정 후 낡은 되돌리기·제안 범위·시간대·블러 검사를 포함합니다. 실제 서버 동작을 증명하지 않습니다.

`TextAppearance.*`와 `dimens.xml`이 폰트 유지 기준 `f8d07c2`와 동일함을 비교했습니다. 확대 글씨 시안/검사 없이 기본 크기만 사용했습니다. 시스템 글자 크기 기능을 강제로 막지는 않습니다.

## 실제 화면·입력 확인

캡처 스크립트로 **79장 전부 다시 촬영**했습니다. 예전 입력 상태 사진을 가져오지 않고 주기 변경 확인·선택 정보 입력·다크 초안·저장 후 상세/수정·완료일 선택·완료/되돌리기까지 현재 스타일로 재생성했습니다. 파일별 SHA는 manifest에 기록합니다.

캡처와 최종 앱의 차이는 삭제된 그림자 대상에 대한 예외 방어와 미사용 ‘오늘’ 문자열 제거뿐이며 시각 규격은 같습니다. 최종 APK도 별도로 설치해 다크 홈에서 다음을 확인했습니다.

- 그림자 View의 상단이 패널보다63px(24dp) 위에 위치함.
- 사진의 상단 날짜 영역에 고정 ‘오늘’ 없이 날짜만 표시됨.
- 펼침→Back 숨김에서 외부 그림자가 함께 사라짐.
- 다시 보기로 기본 높이에 복귀하며 그림자 위치도 복원됨.
- fontScale1.0 유지. 마지막 에뮬레이터는 승인된 다크 홈으로 둠.

HTML은 이미지가 포함된 파일 하나(약26MB)입니다. Chrome157에서 네트워크를 끊고 로컬 파일로 열어79장·라이트/다크·컴포넌트 필터·확대/닫기·1440px/390px에서 가로 넘침 없음을 확인했습니다. 화면 안 버튼은 동작하지 않는 캡처 모음임을 명시했습니다. 공통 상태·날씨 이미지는 라이트 기준으로 두 테마 필터에 함께 표시합니다.

별도 문맥 컴포넌트 검토에서 같은 부모·X/폭·48dp 높이·본문→그림자→패널 그리기 순서·follow 호출 조건을 명시하도록 보완했습니다. 대상 제거 시 그림자를 숨기는 방어도 추가했습니다. 일반 View의 배치/분리까지 포괄하는 별도 계측 테스트는 실행하지 않았습니다.
