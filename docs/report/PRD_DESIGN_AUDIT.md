# PRD 의도와 디자인 정합성 점검

2026-11-10 · 점검 기준 앱 `ac79aeee97226b2e8cf910d98600395c9931d140`

요청은 승인된 화이트·중성 유리·실사 날씨·압축 패널 디자인을 유지하면서, 교체 관리·날씨에 맞춘 집안일·가족 공동 관리라는 제품 목적이 화면과 행동에서 드러나는지 확인하는 것으로 해석했습니다. 실제 서비스 구현과 디자인 미리보기를 구분합니다.

기준은 사용자가 대화에 제공한 S1~S8 화면 명세, 이후 승인한 디자인 변경, [MVP](../MVP.md), [아키텍처](../ARCHITECTURE.md)입니다. Notion PRD/TRD는 커넥터 인증 오류·웹 접근 실패·브라우저 호스트 사용 불가로 최신 원문을 읽지 못했습니다. 원문 전체의 완전 일치 판정은 아닙니다. 제품 충돌은 MVP를 따르고 디자인 8화면·4탭과 실제 캘린더 P1 우선순위를 구분합니다.

## 확인된 보완점

- S2: 작은 패널과 사진을 강조하면서 오늘/지남/임박 요약과 날씨 기반 작업 제안이 기본 화면에서 약해졌습니다. 패널 크기를 바꾸지 않고 사진 아래에서 핵심 행동을 보여줘야 합니다.
- S5/S7: 주간 반복의 표시 기준을 실제 완료일 대신 원래 반복 요일로 유지해야 합니다. 날씨가 좋아도 일률적으로 ‘내일로 변경’을 권하는 예시는 의도를 흐립니다. 변경 이유·동의·그대로 두기를 구분해야 합니다.
- S8: 앱의 알림 설정과 OS 권한 예시가 같은 값으로 취급됩니다. 가족 참여 조건을 설명만 하고 실제 예시 흐름에서는 막지 않는 점, 집장의 구성원 관리 진입이 없는 점도 보완 대상입니다.

범위는 위 디자인·로컬 예시 흐름 보완과 화면별 추적표입니다. Firebase·실제 기상청·알림 예약·OCR 구현을 추가하지 않습니다. 보완 앱 코드는 `faebf0f2e37d9b08674c8333ec4c36f27682debc`입니다. 핵심 목적은 유지하되 약해진 행동 노출과 잘못된 예시 계산을 보완했습니다.

## 이번에 반영한 의도 보완

1. **사진보다 관리 행동이 밀리지 않게 했습니다.** 사진은 유지하고 남은 여백에 두 개의 낮은 행동 행을 배치했습니다. 오늘·지남·임박을 확인해 패널을 펼치고, 세탁 적합도와 작업 제안으로 이동합니다. 장식 카드나 추가 모달을 늘리지 않았습니다.
2. **날씨는 용품 교체일을 바꾸지 않습니다.** 제안 변경은 날씨 민감 집안일에만 적용하고 과거일·같은 날짜·유지 선택을 검사합니다. ‘그대로 두기’는 해당 로컬 예시 일정에 남고 완료나 일정 조건 변경 때 다시 평가할 수 있게 했습니다. 표시된 3일 예보 범위 밖에는 변경을 제안하지 않습니다. 실제 회차 식별자 기반 계약을 구현한 것은 아닙니다.
3. **원래 회차·실행일·완료일을 분리했습니다.** 원래 예정일을 `plannedDue`, 변경된 실행일을 `due`로 구분했습니다. 원래 11/12 목요일 회차를 11/11로 옮기고 11/10에 일찍 완료해도, 다음 회차는 11/19 목요일입니다. 늦게 완료하면 지난 회차를 쌓지 않고 첫 미래 원래 요일로 이동합니다. 이름·장소만 수정해도 실행일·원래 예정일·유지 선택을 되돌리지 않으며, 폼 미리보기와 저장이 같은 계산을 사용합니다.
4. **권한을 켠 것처럼 보이지 않게 했습니다.** 앱 알림 토글과 기기 권한 예시는 서로 다른 상태입니다. 권한 예시는 debug 화면 모음에서 별도로 선택합니다. 실제 시스템 권한 요청·알림 예약은 하지 않습니다.
5. **가족 참여 전에 기존 집을 보호합니다.** 여러 명인 집이나 항목이 있는 1인 집에서는 코드 입력을 차단하고 조건을 안내합니다. 참여를 위해 항목을 자동 삭제·이전하지 않습니다. 집장만 구성원 관리 예시를 열고 내보내기는 확인 후 적용하며 이력을 남깁니다. 다른 가족 항목의 삭제도 일반 구성원에게 비활성화합니다. 실제 보안은 서버 규칙과 별도로 구현해야 합니다.

## 이후 업그레이드 순서와 유지 조건

- **원문 재대조:** Notion 연결 복구 후 PRD/TRD 변경분을 확인합니다. 특히 ‘이번 주’ 범위, 분류 프리셋의 구체 범위, 정원 초과·초대 만료·권한 거부 상태를 확정합니다. 현재 미리보기의 숫자·문구를 근거로 제품 결정을 역으로 확정하지 않습니다.
- **P0 실제 흐름 연결:** [MVP 완료 기준](../MVP.md#구현-순서와-완료-기준)의 개인 교체 관리 → 가족 공유/규칙 → 알림 → 실제 날씨/제안 → 통합 시연 순서를 따릅니다. ViewModel/Repository/domain에 연결하고 Activity에서 Firebase·HTTP를 호출하지 않습니다. 현재 예시는 단일 저장소에서 ID로 찾지만 실제 용품/집안일 저장소 연결에서는 항목 종류와 문서 ID를 모두 전달합니다. 미리보기 코드를 실제 저장소로 간주하지 않고 동일한 테스트 계약을 실제 domain에 옮깁니다.
- **상태 연결:** 서버 대기·오류·권한 거부·오프라인·충돌을 실제 결과에 연결합니다. 화면의 예시 성공 메시지를 실제 성공으로 재사용하지 않습니다. 날짜는 서울 기준, 완료는 서버 확정 뒤 표시, 주간 원래 요일과 이번 회차 실행일을 분리합니다.
- **회귀 기준:** 화이트·중성 유리·실사 사진은 유지하되 교체 요약·날씨 제안 이유·유지 선택·닫기/복귀를 먼저 보호합니다. 패널 확대 없이도 핵심 행동이 보이고 작은 화면·다크 모드에서 접근할 수 있어야 합니다.
- **P1 연결:** 캘린더의 실제 데이터와 사진 OCR은 우선순위를 따로 판단합니다. OCR은 테스트부터 무료인 기존 실험 Gate를 통과하기 전 제품 버튼·저장 경로에 연결하지 않습니다.

범위·제품 규칙은 MVP, 시각 규격은 [디자인 시스템](../DESIGN_SYSTEM.md), 최신 실행 근거는 [이번 검증 기록](evidence/prd-intent/verification.md)을 기준으로 유지합니다. 새로운 색상 시안이 나와도 이 흐름과 권한 계약을 삭제하지 않는 것이 업그레이드 기준입니다.

다음 실제 연결 단위는 개인 교체 관리입니다. 가입 후 자신의 항목을 등록하고, 재실행해도 보존되며, 문서 ID로 같은 상세를 열고, 서버 확정 후 완료·다음 예정일·완료자 이력이 함께 반영되어야 합니다. 실패 시 입력/목록을 보존하고 재시도가 가능해야 하며, 최종 판정은 실제 저장소와 날짜 경계 검사로 합니다.

압축 패널은 요약·펼치기 진입을 위한 상태입니다. 현재 일부 첫 행은 유리 바 뒤로 보이며, 모든 항목을 편하게 읽고 처리하는 상태로 판정하지 않습니다. 펼친 상태에서는 마지막 항목까지 스크롤·선택할 수 있고 하단 바가 필수 행동을 막지 않아야 합니다. 반 높이를 유지하는 후속 개선에서도 이 기준을 보호합니다.

## 검증 결과와 현재 판정

- 최종 앱 코드 `faebf0f2e37d9b08674c8333ec4c36f27682debc`의 기본 빌드·Lint와 단위 테스트 결과 **17개, 실패/오류/건너뜀 0**을 확인했습니다. Lint 오류 0, 고정 도구·의존성 새 버전 안내 경고 15입니다.
- API 36 에뮬레이터에서 홈 요약→펼침·날씨 진입, 제안 유지/변경·예보 범위 제한·오프라인, 가족 참여 차단→조건을 갖춘 참여, 집장 내보내기·이력 유지, 구성원 삭제 가능/불가, 알림 선호/권한 예시 분리를 확인했습니다.
- 최종 코드에서는 주간 조기 완료 후 다음 회차, 이름만 수정할 때의 폼 미리보기/저장, 캘린더 선택 날짜·홈 임박 개수가 같은 항목을 반영하는 것도 확인했습니다. 상세 실행 SHA·최초 검사 중단/재실행과 한계는 [검증 기록](evidence/prd-intent/verification.md)에 분리했습니다.
- 라이트·다크·375dp 홈에서 핵심 행동 진입을 확인했고 최종 전체 화면을 다시 캡처했습니다. 실제 사용자 평가·실기기·두 기기 공유·외부 API·보안 규칙 검증은 아닙니다.

**판정:** 교체를 잊지 않도록 돕고 날씨를 집안일 행동으로 연결한다는 의도는 이번 보완으로 화면과 예시 행동에 더 분명하게 드러납니다. 외형만으로 실제 PRD 기능이 끝났다고 보지 않습니다. ‘이번 주’ 범위는 사용자에게 선택을 요청했으며, 확정 전에는 기존 향후 7일 계산을 보존합니다. 최신 Notion 원문과 이 기간 정의가 남은 확인 항목입니다.
